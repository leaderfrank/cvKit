# 2026-11-08

## Portfolio content refresh (cvKit / my-app)

Rewrote the site content from the 9 tailored CVs in `static/Tailored CVs/`, plus the Google Play
developer page, GitHub profile and Haraj profile.

**Architecture notes**
- All content lives in `src/lib/data/portfolio.ts` (single source of truth). Sections read from it.
- Site is a CSR SPA: `src/routes/+layout.ts` sets `prerender = true` **and** `ssr = false`.
  So `index.html` is only a shell — page `<title>` comes from `svelte:head` client-side.
  Do NOT add a static `<title>` to `app.html`: it produces two `<title>` elements in the DOM.
- `svelte.config.js` adapter-static fallback was changed from `index.html` → `404.html` to stop
  the adapter overwriting the prerendered index (removes the build warning).
- `profile.resume` pointed at `/Mohammed Ghaleb CV.pdf`, which was tracked in git but missing from
  disk. Replaced with `static/Mohammed-Ghaleb-CV.pdf` (copy of the 90% "Best all-rounder" CV).

**Sections (top → bottom)**
Hero → Dashboard → About → Skills → Projects (+ GitHub repos strip) → Apps → Experience →
Education & Certifications → Live APIs → Contact (+ Haraj services).

**Content decisions**
- Title standardised to "Full Stack Developer" (dominant CV headline).
- Testimonials section deleted — it was explicitly placeholder copy and violated the
  "don't invent claims" requirement. Replaced with Education & Certifications.
- 9 Play apps listed with locally-downloaded icons in `static/apps/<packageId>.png`.
- Haraj: only the professional service listings; student/academic listings excluded.

**Build gotcha (this sandbox only)**
`npm run build` fails with `[safe-delete] ... ETIMEDOUT` when a `build/` directory already exists
and a preview server is running. Fix: stop preview, `rm -rf build`, then build.
